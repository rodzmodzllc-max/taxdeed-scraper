# Transfer checklist

Do the steps in order. Steps 1-6 move ownership; steps 7-9 make sure the
seller's credentials no longer work; steps 10-12 put the buyer's details in
the product. Plan a short pause in scheduled harvests (step 2) so no job
writes with old credentials halfway through.

| # | Step | Who | Done when |
|---|---|---|---|
| 1 | Inventory every account in [accounts-and-secrets.md](accounts-and-secrets.md) and confirm the seller can sign in to each | Seller | every row has a named login |
| 2 | Pause the harvest: Actions -> disable `harvest-and-sync.yml`, `schedule-watchdog.yml` and `source-link-check.yml` | Seller | no scheduled run is queued |
| 3 | **GitHub repository**: Settings -> Transfer ownership to the buyer's account or organisation. Afterwards check that the Actions secrets and variables are present; they are re-entered in step 8 anyway. Decide whether the repository stays public (see known-limitations). | Seller, then Buyer | the repository opens under the buyer's account |
| 4 | **Supabase**: transfer project `cqnnnvpbocafuvpzfbzu` to the buyer's organisation (Supabase's project-transfer feature; see Supabase's current docs for where it sits in the dashboard). Check the plan and billing on the receiving organisation first. The project URL does not change, so `config.js` and the secrets stay valid until rotated. | Seller, then Buyer | project listed in the buyer's organisation |
| 5 | **Cloudflare Pages**: move the project serving `rodz-taxdeeds.pages.dev` to the buyer's Cloudflare account (or create a new Pages project on the buyer's account from the transferred repository, production branch `main`, no build command, output = repository root). A new project gets a new `*.pages.dev` name; update the Supabase Auth URLs and the MapTiler origins if so. Reconnect the Git integration to the transferred repository. | Buyer | the site deploys from the buyer's account |
| 6 | **Domain `taxacq.com`**: transfer at the registrar (unlock, auth code) and move DNS. Keep the Pages custom-domain records and the Resend DNS records (SPF, DKIM) exactly as they are during the move. | Seller, then Buyer | domain and DNS in the buyer's account; site and e-mail still work |
| 7 | **Resend**: verify `taxacq.com` in the buyer's Resend account, create two API keys (one for Edge Functions, one for Supabase Auth SMTP). | Buyer | test e-mail delivered |
| 8 | **Rotate every secret** (the seller has seen all of them): Supabase secret / service-role key -> Actions secret `SUPABASE_SERVICE_KEY`; Supabase publishable key -> root `config.js` `supabasePublishableKey`; `RESEND_API_KEY` (Edge Function secret) and the Auth SMTP password; `SCRAPERAPI_KEY` (or drop it); `GOOGLE_MAPS_API_KEY` (or drop it); OpenPGP pair -> `ARTIFACT_PUBLIC_KEY` / `ARTIFACT_PRIVATE_KEY`; `NOTIFY_WEBHOOK_SECRET`, `DIGEST_CRON_SECRET` if set; Stripe keys if billing was ever configured. Then revoke every old key. | Buyer | every old key revoked; one manual `job=laft` run succeeds |
| 9 | **Map keys**: issue new MapTiler and Google Maps keys on the buyer's accounts, restricted to the buyer's domains (MapTiler "Allowed HTTP Origins"; Google HTTP referrers + Maps JavaScript API only, on a billed project, replacing the Demo Key). Put them in root `config.js` (`maptilerKey`, `googleMapsApiKey`). Revoke the seller's keys. | Buyer | both basemaps render on the live site |
| 10 | **Product details in root `config.js`**: `supportEmail`, `legal.operatorName`, `legal.governingLaw`, `legal.effectiveDate`, `legal.contactEmail`. Also the fixed addresses in `supabase/functions/_shared/approval_notify_core.js` (sender, reply-to, new-sign-up alert recipient) if the mailbox changes; then redeploy `self-signup` and `notify-approval`. | Buyer | legal pages show the buyer's entity |
| 11 | **Supabase Auth settings**: Site URL, Redirect URLs, SMTP sender, e-mail templates (`docs/production-configuration.md` section 2, `docs/auth-email.md`). Make the buyer's account an admin (`profiles.is_admin`) and remove the seller's admin flag. | Buyer | password reset e-mail arrives and its link works |
| 12 | **Repository text**: CLAUDE.md's "Where to look for more" points to a claude.ai Project (`claude/improvement-roadmap.md`) the buyer will not have; everything needed is in the repository. Replace that pointer with the buyer's own changelog location. Update owner names ("Marc") where they describe who holds an account. | Buyer | - |
| 13 | Re-enable the workflows from step 2. Watch one full day: both `deeds` runs, both `37`-minute runs, the link check. | Buyer | admin "Needs attention" shows no new failures |
| 14 | Review [known-limitations.md](known-limitations.md) and `docs/legal/pre-sale-blockers.md`: the interim source permissions were accepted by the seller and expire 2027-04-12; they do not transfer as permission. | Buyer, Counsel | a decision recorded per open item |
