# Buyer's Guide - data contract (backend -> front end)

Owner's request (2026-10-28): a buyer's guide for every state, county and ledger we carry - the questions a
buyer asks before acting, each answered from an official source, or plainly marked as not yet verified with
where to look. Shown per county (from a county's page, a property page, or the guide page), not stacked at the
top of every screen. Access may later depend on the tier (Guided users included; possibly a paid extra) - the
front end handles that with `config.js` `buyersGuideAccess`; the data never depends on it.

The **backend** produces the data; the **front end** (`public/buyers-guide.js`) only displays it. Until the file
exists the page falls back to `public/state-rules.json` (verified rules and county procedures already on file).

## File

`public/buyers-guide.json` (generated, mirrored to the repo root, added to the mirror `FILES` list and
`DEPLOYED_BUNDLE_FILES`; a `--check` test pins it like `state-rules.json`). Builder:
`scripts/build_buyers_guide.py` from `data/buyers_guide_questions.csv` + `data/buyers_guide_answers.csv`
(+ the existing rules / evidence tables it can reuse).

```json
{
  "_comment": "Generated by scripts/build_buyers_guide.py - do not edit.",
  "generated_at": "2026-10-29",
  "statuses": {"VERIFIED": "...", "PARTIALLY_VERIFIED": "...", "NOT_VERIFIED": "...", "SOURCE_RESTRICTED": "..."},
  "ledgers": {"AUCTIONS": "Auctions", "AVAILABLE": "Available", "LIENS_CERTIFICATES": "Liens & Certificates"},
  "questions": {
    "AUCTIONS": [{"id": "register", "question": "How do I register to bid?", "group": "Before the sale", "level": "beginner"}],
    "AVAILABLE": [...], "LIENS_CERTIFICATES": [...]
  },
  "states": {
    "FL": {
      "name": "Florida", "unit": "County",
      "ledgers": {
        "AUCTIONS": {
          "offered": "OFFERED | NOT_OFFERED | COUNTY_DEPENDENT | NOT_VERIFIED",
          "summary": "one plain sentence, or null",
          "answers": [ANSWER, ...]
        }
      },
      "counties": {
        "Leon": {"AUCTIONS": {"answers": [ANSWER, ...]}, "AVAILABLE": {...}}
      }
    }
  }
}
```

`ANSWER`:

```json
{
  "q": "register",                       // a question id of that ledger
  "status": "VERIFIED",                  // VERIFIED | PARTIALLY_VERIFIED | NOT_VERIFIED | SOURCE_RESTRICTED
  "answer": "plain-English answer, 1-3 sentences, no legal advice wording",
  "quote": "the source's own words the answer rests on (VERIFIED/PARTIALLY_VERIFIED only)",
  "source_url": "https://...",           // official page or document (https only)
  "source_title": "Leon County Clerk - Tax Deed Sales",
  "citation": "F.S. 197.542(2)",          // optional
  "office": "Clerk of the Circuit Court", // optional: who handles it
  "verified_on": "2026-10-30",           // VERIFIED / PARTIALLY_VERIFIED only; the date the page was read
  "where_to_look": "who / which page answers it, for NOT_VERIFIED"
}
```

Rules the front end relies on:
- A county answer replaces the statewide answer for the same question in that county only; a question with
  neither shows "Not yet verified" + `where_to_look` from the question default.
- `VERIFIED` only from a page/document actually read (a capture run, never a search snippet), with `quote`,
  `source_url` and `verified_on`. A search-result lead is `NOT_VERIFIED` with the URL in `where_to_look`.
- Never a number that is not in the quote (deposit %, interest rate, redemption period, fees).
- No owner names, no row values; answers are about the process, never about one property.
- Ledger names and unit words come from the file (`unit`: County / Parish).

## Question catalog (suggested; the backend owns `data/buyers_guide_questions.csv`)

AUCTIONS: how_it_works, where_when (online platform / courthouse, schedule), register, deposit,
opening_bid (what the opening / minimum bid is made of), pay_after_win (how and by when), extra_costs
(recording, doc stamps, other fees), what_you_get (deed type), redemption_after_sale, liens_survive,
title (insurability / quiet title), occupied, unsold (what happens if nobody bids), surplus.

AVAILABLE: what_is_list, how_to_buy, price (what the listed figure is), extra_costs, application
(form, where to submit), pay, what_you_get, timeline, liens_survive, title, inspect, refunds.

LIENS_CERTIFICATES: what_is_it, how_to_buy (auction / over the counter / assignment), interest_return,
redemption_period, if_not_redeemed (how to apply for the deed), costs, risks (worthless parcels,
bankruptcy, expiry), assignment.
