# All-sources AVAILABLE enrichment engine

Sprint of 2026-10-01. The goal is to raise the verified customer value of
every AVAILABLE property in every supported state, using every legitimate
source the project knows about. Governance is one dimension of a source. It
never organises the work.

## 1. The pipeline, stage by stage

Each stage has its own module:

| Stage | Where |
|---|---|
| Source discovery | `scripts/discover_sources.py` (GIS catalogs, official documents) and `data/enrichment_source_catalog.csv` (known, not-yet-used sources) |
| Source access | `UnifiedSource.access` (ACCESSIBLE / SOURCE_UNAVAILABLE / NOT_CHECKED / NOT_ACCESSED_BLOCKED), from capture runs and registry verification |
| Data extraction | `harvesters/documents/extract.py` (PDF text, tables, OCR, CSV) and the parcel factory `harvesters/enrichment/parcels.py` |
| Property matching | deterministic identifier rules (`parcels.ID_RULES`), on both sides; two candidates = AMBIGUOUS, nothing written |
| Enrichment | `scripts/enrich_available.py` (parcel layers) and the existing NAIP / FEMA / Census runners |
| Provenance | `field_provenance` per column (source, dataset, layer URL, matched identifier, licence, recorded time); documents carry URL, title, document date, page, extraction time |
| Governance | `harvesters/sources/model.py`: APPROVED / REVIEW_REQUIRED / HARD_BLOCKED |
| Publication | the registry's per-source `publication_status` and the publication gate, unchanged by this engine |

## 2. One source model (`harvesters/sources`)

`UnifiedSource` puts every source in one shape. It carries:

- state, county, name, publisher and URL;
- the source type: GOVERNMENT, DOCUMENT, GIS, COURT_PUBLIC_RECORD,
  PUBLIC_NOTICE, AUCTION_VENDOR, THIRD_PARTY or FEDERAL_DATASET;
- roles: which customer dimensions the source can fill;
- governance and its reason, access and its note, evidence, last checked,
  next action, and the legacy status as originally written.

`inventory.build_inventory()` assembles 318 sources across all 13 registered
states from:

- the county source registry;
- the parcel layer configs;
- the federal datasets the enrichers call;
- the verified acquisition evidence;
- the acquisition candidate pages, with their last capture outcome
  (`data/acquisition_capture_outcomes.csv`);
- the catalog of known sources not yet used.

### Governance mapping

The mapping is mechanical, and every override cites its basis:

| Older vocabulary | Unified |
|---|---|
| APPROVED, APPROVED_GRANDFATHERED | APPROVED |
| UNREVIEWED, RESTRICTED, blank | REVIEW_REQUIRED |
| BLOCKED (blocked vendors) | HARD_BLOCKED |

There are two documented overrides. `tx_lgbs` and `tx_realauction` run under a
grandfathered approval, but their own Phase 10B rights audits found open
LEGAL_REVIEW_REQUIRED findings, so the unified model calls them
REVIEW_REQUIRED. The registry's publication decision for rows already served
is NOT changed.

### What each governance state permits

| Governance | May be requested | May write customer fields |
|---|---|---|
| APPROVED | yes | yes |
| REVIEW_REQUIRED | yes (discovery and verification counts) | no |
| HARD_BLOCKED | never | never |

One REVIEW_REQUIRED source never stops another source from being used.

### Admin source panel

`admin.html` lists the inventory (`public/source-inventory.json`, generated by
`scripts/build_source_inventory.py`; a test fails while it is stale). The list
is joined with the registry's live freshness columns. It can be filtered by
state, governance and type. Each row shows:

- reason and access;
- last checked;
- last successful read;
- last failure;
- next action.

## 3. Documents are first-class (`harvesters/documents/extract.py`)

- **Reading.** `read_document()` reads text PDFs page by page, including
  tables, and takes the title and date from the PDF metadata. CSV and text
  are read too.
  - **Scanned pages** are OCR'd when `pytesseract` and `tesseract` exist; the
    discover job installs both.
  - **Without OCR**, the document reports `OCR_UNAVAILABLE`, and nothing is
    guessed from its images.
- **Matching.** `find_identifier_records()` matches a property identifier
  only as a whole token, normalized with the same rule on both sides. Two
  different lines for one identifier make it AMBIGUOUS.
- **Acquisition facts.** `acquisition_facts()` extracts office contacts
  (phone, e-mail, PO box) and the process, payment, deadline and deposit
  sentences, each with its page number.
- **Notices.** `notice_records()` extracts the dates and amounts on a matched
  identifier's own line.
- **Provenance.** Every result carries the source URL, the document
  title / date, the page and the extraction time. A document's text is never
  stored or republished whole.

## 4. The engine (`scripts/enrich_available.py`)

Every active AVAILABLE row of every production state is read, paged by id.
Each row has fourteen customer dimensions:

1. identity
2. legal description
3. assessment
4. acreage
5. land use
6. coordinates
7. imagery
8. flood
9. acquisition path
10. acquisition contact
11. instructions
12. source document
13. source date
14. provenance

### Gap outcomes

A missing dimension gets exactly one outcome:

| Outcome | Meaning |
|---|---|
| `SOURCE_FOUND` | an APPROVED, accessible source covers it; eligible for the next pass |
| `NEEDS_COORDINATES` | imagery / flood need coordinates first |
| `SOURCE_REVIEW_REQUIRED` | only REVIEW_REQUIRED sources cover it |
| `SOURCE_HARD_BLOCKED` | only HARD_BLOCKED sources cover it |
| `SOURCE_UNAVAILABLE` | the approved source refused the runner (HTTP 403, unreachable) |
| `SOURCE_EMPTY` | the approved pages were read and do not publish it |
| `SOURCE_PARSE_FAILED` | the page renders its process by script |
| `NO_SOURCE_FOUND` | nothing in the inventory covers it |
| `MATCH_FAILED` | the parcel layer ran and the identifier did not resolve to exactly one feature |

### Availability

Every row is also VERIFIED_AVAILABLE (approved source, read within 14 days) or
NOT_VERIFIED_AVAILABLE, with the reason. Texas rows are "manual-only source; no
read recorded since read-stamping". Availability is measured, never acted on:
no row is closed, hidden or marked stale by the engine.

### Coverage matrix

The matrix is per state × county. For each county it gives:

- AVAILABLE records;
- sources discovered and accessible;
- sources APPROVED / REVIEW_REQUIRED / HARD_BLOCKED;
- government, document, GIS, court, notice, vendor and federal sources;
- records matched;
- rows enriched / partially enriched;
- rows with an acquisition path, coordinates, legal description, assessment
  or imagery;
- the gap outcomes per dimension;
- the last successful read.

It is written to `out/public/available-enrichment-<label>.json` and the job
summary. Counts only.

### Modes (`job=available`, `available_mode`)

| Mode | What it does |
|---|---|
| `plan` | Read-only. The coverage matrix, plus the parcel enricher's real queries and matches, so its expected writes are measured. Imagery / flood / geocode expected work is computed from the rows and the storage headroom. |
| `discover` | `scripts/discover_sources.py --gis --documents`. ArcGIS Online + Socrata catalog search per AVAILABLE county; field names, licence / access-information and copyright text; an identifier match probe (`returnCountOnly`); every official document the inventory names, read through the document pipeline. Value-free: digit runs of 5 or more are masked; identifiers never leave memory. |
| `apply` | The cleared parcel layers write through `field_provenance` precedence: a blank is filled; a stronger value is never replaced. Then NAIP imagery (AVAILABLE first; the 950 MB budget fails closed; deferred rows stay unchecked) and FEMA flood run for LA / TX / FL, then the plan again. Every apply step is `continue-on-error`: one enricher failing never stops the next. |

## 5. Parcel layers can be county-scoped

`ParcelSourceConfig.counties` scopes a layer to named counties. With it, a
county appraisal district's layer can sit beside a state's statewide layer
(`sources.for_county()` lists county-scoped layers first). No two scoped
layers may overlap.

## 6. What this engine does not do

- It does not run LGBS or any blocked vendor, and it does not schedule the
  texas job.
- It does not write a REVIEW_REQUIRED source's values.
- It does not infer sold, redeemed, available or withdrawn status from
  absence.
- It does not match on owner name or a bare address.
- It does not change publication status, auction outcomes, schedules or
  storage policy.
- It applies no migration.
